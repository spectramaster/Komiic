## 项目概述

### 项目愿景
创建一款革命性的嵌入式编程学习应用，通过游戏化设计让STM32学习从"枯燥的技术文档"变成"令人上瘾的冒险旅程"。

### 目标用户
- **主要用户**：电子工程/计算机专业学生（18-25岁）
- **次要用户**：嵌入式开发入门者、硬件爱好者
- **痛点**：
  - 嵌入式学习曲线陡峭
  - 缺乏实时反馈和成就感
  - 需要购买昂贵的开发板
  - 传统教程枯燥乏味

### 核心价值主张
> "不需要开发板，不需要焊接，只需要打开软件，像玩游戏一样掌握STM32编程"

## 核心设计理念

### 1. 游戏化学习三原则

#### 原则一：即时反馈循环
```
编写代码 → 即时编译 → 虚拟硬件响应 → 视觉/听觉反馈 → 成就感 → 继续学习
```
- 代码每次保存自动编译（<500ms）
- 虚拟LED实时闪烁
- 错误提示带有友好的动画和音效
- 成功时的多巴胺奖励（特效、音效、分数）

#### 原则二：渐进式挑战
- **新手保护期**（第1-3关）：可视化编程，无法失败
- **技能建立期**（第4-15关）：引导式编程，提供框架
- **自主掌握期**（第16-30关）：开放式挑战
- **大师级**（30关+）：性能优化、创意项目

#### 原则三：社交驱动力
- 排行榜激发竞争
- 代码分享促进学习
- 协作模式培养社区

## 核心游戏机制

### 1. 编程界面设计

#### 三种编程模式（难度递进）

**模式A：可视化编程（1-3关）**
```
┌─────────────────────────────────┐
│ [拖拽代码块]                      │
│                                 │
│  ┌──────┐  ┌──────┐  ┌──────┐  │
│  │ 初始化 │→│ 循环  │→│ 延时  │  │
│  └──────┘  └──────┘  └──────┘  │
│                                 │
│  ⬇ 自动生成代码                  │
│  while(1) {                     │
│    LED_Toggle();                │
│    Delay(500);                  │
│  }                              │
└─────────────────────────────────┘
```

**模式B：填空式编程（4-15关）**
```c
// 任务：让LED每秒闪烁一次
void LED_Task(void) {
    GPIO_InitTypeDef GPIO_InitStruct;

    // TODO: 填写时钟使能代码
    ____________________;

    // TODO: 配置GPIO模式
    GPIO_InitStruct.Mode = ___________;
    GPIO_InitStruct.Pin = ____________;

    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

    while(1) {
        // TODO: 切换LED状态
        ____________________;
        HAL_Delay(______);
    }
}
```

**模式C：自由编程（16关+）**
- 完整的代码编辑器
- 智能代码补全
- 实时错误检测
- 性能分析器

#### 代码编辑器功能

**智能提示系统**
- 输入`HAL_`自动弹出所有HAL库函数
- 鼠标悬停显示函数原型和说明
- 错误下划线（红色波浪线）+ 修复建议

**实时编译**
- 保存时自动编译（Ctrl+S）
- 编译进度条（带芯片充能动画）
- 错误列表可点击跳转

**调试可视化**
- 单步执行时高亮当前行
- 变量监视窗口显示寄存器值
- 调用堆栈可视化

#### 示例关卡：1-1 觉醒之光

**学习目标**：GPIO输出，LED控制

**剧情**：
> 艾达博士："欢迎来到芯片世界！你面前的是一颗沉睡的STM32芯片。看到那盏灯了吗？用你的代码点亮它，证明你有成为芯片唤醒师的天赋！"

**任务**：
1. 配置GPIOC Pin13为输出模式
2. 让LED每秒闪烁一次
3. 闪烁10次后保持常亮

**提供的框架代码**（填空模式）：
```c
void MissionOne(void) {
    // 步骤1: 使能时钟
    __HAL_RCC_GPIOC_CLK_ENABLE();

    // 步骤2: 配置GPIO
    GPIO_InitTypeDef GPIO_InitStruct = {0};
    GPIO_InitStruct.Pin = GPIO_PIN_13;
    GPIO_InitStruct.Mode = ____________;  // 提示：输出模式
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);

    // 步骤3: 闪烁10次
    for(int i = 0; i < ____; i++) {  // 提示：循环次数
        HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
        HAL_Delay(____);  // 提示：1秒 = ? 毫秒
    }

    // 步骤4: 保持常亮
    HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, ________);
}
```

**测试条件**：
- ✅ LED成功闪烁10次
- ✅ 闪烁频率1Hz（±10%）
- ✅ 最后保持常亮

**奖励**：
- 经验值：100 XP
- 解锁：GPIO技能徽章（铜）
- 代码模板：LED控制基础模板

### 关键技术实现

#### 1. 虚拟STM32实现方案

**方案A：基于QEMU（推荐）**

优势：
- 成熟的ARM指令模拟
- 已有STM32支持
- 性能好

实施步骤：
1. 编译QEMU STM32分支
2. 通过QMP（QEMU Machine Protocol）与Qt通信
3. 定制外设行为（GPIO → Qt信号）

```cpp
// 伪代码
class STM32Emulator : public QObject {
    Q_OBJECT
public:
    void runCode(QString code) {
        // 编译代码
        QString binary = compile(code);

        // 加载到QEMU
        qemuProcess->loadBinary(binary);

        // 监听GPIO变化
        connect(qemu, &QEMU::gpioChanged,
                this, &STM32Emulator::onGPIOChanged);

        // 运行
        qemuProcess->run();
    }

signals:
    void ledStateChanged(int pin, bool state);
    void uartDataReceived(QByteArray data);
};
```

**方案B：自研轻量级模拟器**

适用于：教学目的，不需要100%精确

```cpp
class SimpleSTM32 {
    // 寄存器模拟
    uint32_t GPIOA_ODR;
    uint32_t TIM2_CNT;

    // 外设模拟
    void setGPIO(uint8_t pin, bool state) {
        if(state) GPIOA_ODR |= (1 << pin);
        else GPIOA_ODR &= ~(1 << pin);

        emit gpioChanged(pin, state);
    }

    // 定时器模拟（简化）
    void timerTick() {
        TIM2_CNT++;
        if(TIM2_CNT >= TIM2_ARR) {
            TIM2_CNT = 0;
            // 触发中断
            handleTimerInterrupt();
        }
    }
};
```

#### 3. 实时编译实现

```cpp
class CodeCompiler : public QObject {
    Q_OBJECT
public:
    void compile(QString sourceCode) {
        // 1. 保存到临时文件
        QString tmpFile = "/tmp/user_code.c";
        QFile file(tmpFile);
        file.write(sourceCode.toUtf8());

        // 2. 调用GCC编译
        QProcess *gcc = new QProcess;
        gcc->start("arm-none-eabi-gcc",
                   QStringList() << "-mcpu=cortex-m3"
                                 << "-o" << "/tmp/output.elf"
                                 << tmpFile);

        connect(gcc, &QProcess::finished, [this](int code) {
            if(code == 0) {
                emit compileSuccess("/tmp/output.elf");
            } else {
                QString errors = gcc->readAllStandardError();
                emit compileError(parseErrors(errors));
            }
        });
    }

signals:
    void compileSuccess(QString binaryPath);
    void compileError(QList<CompileError> errors);
};
```

## 风险与挑战

### 技术风险

1. **STM32模拟精度**
   - 挑战：完全模拟硬件很难
   - 方案：教学级模拟（80%精度即可）

2. **性能问题**
   - 挑战：实时编译+模拟可能卡顿
   - 方案：增量编译、多线程、GPU加速

### 市场风险

1. **目标用户规模**
   - 挑战：嵌入式学习者相对小众
   - 方案：扩展到Arduino、树莓派等平台

2. **竞品压力**
   - 现状：目前无直接竞品
   - 预防：快速迭代，建立护城河

### 教育风险

1. **知识准确性**
   - 挑战：游戏化可能简化过度
   - 方案：专家审核、提供深入文档链接
